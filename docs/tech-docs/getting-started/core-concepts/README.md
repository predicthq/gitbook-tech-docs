# Core concepts

The ideas the rest of the docs build on. If you read nothing else before integrating, read these - most integration mistakes come from skipping them.

Recommended order:

1. [Event-driven demand](event-driven-demand.md) - why real-world events move demand, and the four challenges any integration has to solve
2. [What is Beam?](what-is-beam.md) - the relevancy engine that calibrates everything downstream
3. [What is the Features API?](what-is-the-features-api.md) - model-ready signals instead of raw event aggregation
4. [Which API should I use?](which-api-should-i-use.md) - the right tool per task, including grounding
5. [Data Leakage in Backtesting](data-leakage-in-backtesting.md) - why forward-looking features evaluate honestly

[Guide to protecting PredictHQ data](guide-to-protecting-predicthq-data.md) covers the obligations that come with using the data.

For the recommended path by job - training, grounding, managed forecasts, or demand analysis - start with [How to use PredictHQ](../how-to-use-predicthq.md).
